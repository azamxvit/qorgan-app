# Mobile UX Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans for integration; independently owned service and content tasks can run in parallel under superpowers:dispatching-parallel-agents. Steps use checkbox syntax for tracking.

**Goal:** Implement the approved account-free mobile UX, retaining QorganColors and the existing brand.

**Architecture:** Keep Flutter, the local classifier and storage. Extend service capabilities without changing classifier rules. The shell owns first-run routing, three persistent tabs and notification navigation; focused pages own setup, settings, manual results and message history.

**Tech Stack:** Existing Flutter/Dart, SQLite, shared_preferences and Android plugins; no new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-07-mobile-ux-design.md`, approved by user on 2026-11-07 with existing color tokens preserved.

## Global Constraints

- Preserve every current QorganColors value; use existing tokens, including dark/pale/backdrop, for risk distinctions.
- No accounts, login, guest mode, backend, demo SMS, changes to domain thresholds or blocklist work.
- Existing workspace has extensive uncommitted work required by this UX. Work in place without resetting, staging or committing unrelated files.
- Authored UI remains Russian and supports 320px width and 200% text scaling.
- Only new incoming SMS are stored, maximum 100; manual results stay in session memory.
- TDD for meaningful state transitions, storage and notification semantics; visual changes are checked through widget layout and screenshots.

## Review Focus

- Cold notification launch for an evicted record must not open another SMS (Task 1 + 4).
- SMS arrival during storage clear/refresh must not erase later records or lose refresh (Task 1).
- Interrupted permission setup / persist failure must not claim protection enabled (Task 1 + 3).
- Large text, long sender, keyboard and scrolling must preserve reachable actions (Task 2 + 4).
- Editing manual text, switching tabs and backgrounding must preserve a draft but never reuse a stale result (Task 2 + 4).
